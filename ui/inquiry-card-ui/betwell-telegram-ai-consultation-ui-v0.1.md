## 0 · 模式确认(2026-06-03)

经决策选定:**混合模式 + 抽卡卡片 + 后台档案 + TG 预览**

- **混合模式** = 患者先与 AI bot 单聊完成预问诊 → 再进医患三方群与医生对话 · AI 继续在群里抽卡补漏
- **抽卡卡片** = 每次给患者 1-3 张预设问题卡 · Inline Keyboard 点选 · 不是自由打字
- **后台档案** = 完整 SOAP + IoT + 抽卡轨迹存 Betwell 后台数据库 · 不传 TG
- **TG 预览** = TG 内只发结构化摘要 + 查看完整档案链接(带 token)

## 2 · 流程 1 · 患者预问诊(AI Bot 单聊)

### 2.1 进入路径

- 度假村入住前 7 天 · 客服(L3 个人执业师)发 TG 邀请链接 → 患者点击 → 进入 `@betwell_bot` 私聊
- 患者首次 `/start` · Bot 自我介绍 + 隐私告知 + 同意书确认

### 2.2 抽卡卡组(6 张固定卡 · MVP 版本)

| 卡号 | 卡名 | 卡片类型 | 选项数 | 输出字段 |
|---|---|---|---|---|
| **C1** | 主诉部位 | 单选 + 逃生 | 5 个部位 + 自由文字 | `chief_complaint_location` |
| **C2** | 症状性质 | 单选 + 逃生 | 5 性质 + 自由文字 | `symptom_quality` |
| **C3** | 持续时间 | 单选 | 4 时段 | `duration_bucket` |
| **C4** | 伴随症状 | 多选 + 逃生 | 8 选项 + 自由文字 | `associated_symptoms[]` |
| **C5** | 既往史 + 用药 | 二级单选 | 无 / 有→自由文字 | `medical_history` + `current_medications` |
| **C6** | 确认摘要 | 复核 + 提交 | [确认] [改] | `confirmed_at` + 触发档案生成 |

### 2.3 抽卡纪律

- **每张卡不超过 5 个一级选项** · 超过拆两张
- **始终留"自由文字"逃生口** · 每组卡片底部有 `[让我自己说]` 按钮
- **进度条**:消息开头 `[已完成 3/6 · 大约还需 2 分钟]`
- **每答完一张 · AI 即时回应**:"明白 · {字段总结} · 我记下来了"
- **不允许跳卡** · 必须按 C1→C6 顺序(MVP 阶段不做条件分支)

### 2.4 隐私告知卡(`/start` 后第一张)

```
你好 · 我是健愈 AI 助理 · 我会问你 6 个问题
帮医师提前了解你的情况 · 大约 5 分钟。

你的回答会进入你的健康档案:
- 完整档案存 Betwell 后台 · 你随时可查可删
- TG 上仅显示摘要 · 不会泄露身份信息
- 医师看完会和你直接沟通

[我同意 · 开始]  [我有疑问 · 联系客服]
```

不点同意 · 不进入抽卡。

## 3 · 流程 2 · 医患三方群(AI 旁路)

### 3.1 群组成

- 群名:`{患者名} · {医师名} · 健愈群`(例:张三 · 李医师 · 健愈群)
- 成员:患者 + 医生 + `@betwell_bot`(管理员权限 · 用于发档案预览和静默监听)
- 群头像:Betwell logo

### 3.2 AI 在群里的行为规则

| 触发 | AI 动作 | 可见范围 |
|---|---|---|
| 群建立 | 发预问诊摘要卡片(SOAP S 段) | 全员可见 |
| 医生 / 患者自由对话 | 静默监听 · 不发言 | — |
| 检测到新症状 / 矛盾信息 | 给医生 DM 发"建议补问"卡 | **仅医生** |
| 医生 `@betwell_bot 抽 X 卡` | 在群里抽指定卡组(例:过敏史) | 全员可见 |
| 问诊结束(医生 `/finish`) | 发完整 SOAP 档案预览卡 + 查看链接 | 全员可见 |

### 3.3 关键 UI 元素

**预问诊摘要卡**(群建立时):
```
📋 预问诊摘要 · 张三 / 6-03 09:50
─────────────────────────────────
主诉:头部胀痛 · 持续一周
性质:胀 + 间歇性
伴随:失眠 · 颈部僵硬
既往:高血压 5 年 · 服氨氯地平
过敏:无

[查看完整档案] [开始问诊]
```

**建议补问卡**(DM 给医生 · 非群内):
```
ⓘ 检测到新症状:晨起加重
建议补问:
• 血压晨起测过吗?
• 枕头高度?

[插入到群对话] [仅我可见] [忽略]
```

医生点 `[插入到群对话]` · Bot 在群里以**医生口吻**发问(不暴露 AI 来源):
```
李医师(发送的实际是 Bot 代发):
"晨起加重对吗?血压晨起测过吗?枕头高度?"
```

### 3.4 AI 永不替代医师说话的红线(对应 D-AI 决策 3)

| 允许 | 不允许 |
|---|---|
| AI 给医生发建议 | AI 直接在群里以自己名义指导患者 |
| 医生授权后 AI 代发抽卡 | AI 未授权直接问患者新问题 |
| AI 整理对话为结构化数据 | AI 给出诊断结论 / 处方建议(只能医生给) |
| AI 推送 IoT 数据预警 | AI 替医生改预约 / 改用药 |

## 4 · 流程 3 · 档案输出(双轨)

### 4.1 TG 内预览卡(问诊结束 · 群里发)

```
📋 问诊档案 · #20260603-0001
─────────────────────────────────
患者:张三 (subject_id: P-1234)
医师:李医师 (D-5678)
时间:6-03 09:35 - 10:12

S 主观:头部胀痛一周 · 晨起加重
O 客观:血压 145/95(晨)
A 评估:疑似 H 型高血压
P 计划:加做颈椎 MR · 监测晨血压

下次随访:6-10(AI 自动提醒)

[查看完整 PDF] [患者签字] [入库]
```

### 4.2 后台完整档案(数据库 · 不进 TG)

完整 SOAP + IoT + 抽卡轨迹 + 师傅手法(L3 角色)+ 审计日志 · typed schema 详见 `intake-card-typed-schema.json` 和 `consultation-record-schema.json`(后者待 P1 补)。

### 4.3 链接安全(隐私合规)

- "查看完整档案" 链接形如:`https://app.betwell.io/r/{short_token}`
- short_token 有效期 24 小时 · 单次使用
- 点击后需 TG 账号二次验证(OAuth 通过 Bot)
- 不暴露 patient_id / doctor_id / 任何 PHI

## 5 · 三纪律(对应已立决策卡)

| 纪律 | 锚 | UI 体现 |
|---|---|---|
| **主体显式** | D-AG | 每条档案带 `subject_id`(P-1234)· 不靠"张三"姓名推断 · 名字可重 · ID 不可重 |
| **对象化 typed schema** | D-AI | 抽卡每张 = 一个 typed object · 不是 free text 大块塞给 LLM · 字段 / 类型 / 必填性显式定义 |
| **AI 不替代专家说话** | D-AH + D-AI 决策 3 | 三方群里 AI 只给医生 DM 建议 · 不直接对患者发指令 · 副作用全经医生审核 |

## 6 · 三张力 · 不掩盖

### 张力 1 · TG Bot UI 上限

Telegram Bot 的 Inline Keyboard 最多 8 列 · Reply Keyboard 不支持图片卡片 · 复杂表单只能拆多步。

**应对**:
- MVP / P0 用 Inline Keyboard · 6 张抽卡足够
- P2 升级 Telegram Web App(Bot 弹出小程序 · 在 TG 内打开 H5)· 支持图片 / 视频 / IoT 数据展示
- 不要每场景都拉 Web App · 过度工程

### 张力 2 · 三方群里 AI 抢话

如果 AI 自动发"建议补问"卡片到群里 · 患者会被分散注意 · 医生话语权被稀释。

**应对**:
- AI 默认所有补问发**医生 DM** · 不发群
- 群里只发**节点性输出**(预问诊摘要 + 档案预览)· 不是过程性插话
- 群内消息密度上限:每场问诊 AI 不超过 3 条群消息

### 张力 3 · TG 数据合规

TG 服务器在迪拜 / 海外 · 患者 PHI 走 TG 一遍 · 触 HIPAA / 国内《个人信息保护法》/ 马来西亚 PDPA。

**应对**(工程层 · 非 UI 层):
- TG 仅传:`subject_id` + 结构化症状字段 + 时间戳
- 不传:姓名 / 身份证 / 完整病史 / 处方 / 诊断
- 完整档案存 Betwell 后台 · TG 里只发短 token 链接
- **关联 Betwell 决策:不在中国落地** · 即使柔佛州 · PDPA 也得过
- 启用前必须法律审查 · 不在 v0.1 范围

## 7 · 反模式清单(不允许做的)

| 反模式 | 为什么不做 |
|---|---|
| AI 在三方群里直接问患者(不经医生授权) | 患者会以为是医生在问 · 出事归属不清 · 违反 D-AG 主体链 |
| 抽卡选项给 6+ 个让患者翻页 | 选择疲劳 · 中途流失率从 15% 飙到 40%+ |
| 完整 SOAP 档案直接发 TG 群文本 | 隐私合规 + 屏幕滚动地狱 · 用链接 + PDF |
| AI 自动给患者发"健康建议" | LLM 直接执行副作用 · D-AI 决策 3 红线 |
| 抽卡问题用纯 emoji 不带文字 | 老年患者看不懂 · L1 客人很多 50+ |
| 跳卡 / 条件分支(MVP 阶段)| 增加状态机复杂度 · P1 再加 |

## 8 · 落地路径(P0 / P1 / P2)

### P0 · MVP(1-2 周)

**目标**:验证抽卡问诊 + 后台档案能跑通 · 暂不做三方群。

清单:
- [ ] 患者 + Bot 单聊预问诊(流程 1) · 6 张固定卡组
- [ ] typed schema 落到 Postgres / SQLite(`intake_cards` 表)
- [ ] 问诊结束 · Bot 把 SOAP 摘要文本发给医生 DM
- [ ] 后台 JSON 存档 · 暂不做 PDF
- [ ] 隐私同意书弹窗 + 短 token 链接

**成功标准**:10 次真实问诊 · 抽卡完成率 ≥ 80% · 医生 DM 收到结构化摘要。

### P1 · 三方群版本(再 2-3 周)

清单:
- [ ] 拉三方群自动化(`/handoff {doctor_id}`)
- [ ] AI 旁路监听 + DM 建议补问卡
- [ ] 医生 `[插入对话]` / `[仅我可见]` 权限按钮
- [ ] 档案预览卡 + 完整 SOAP PDF 导出

**成功标准**:10 次真实三方群问诊 · 医生反馈 AI 补问"有用率" ≥ 60%。

### P2 · Web App 完整版(再 4-6 周)

清单:
- [ ] 抽卡升级为 TG Web App(图片 / 视频 / IoT 数据展示)
- [ ] 完整 SOAP 编辑器 + 数字签字 + 长期档案管理
- [ ] L3 个人执业师手法记录卡(度假村现场)
- [ ] 多语言(中 / 英 / 马来语 · 对应柔佛州场景)
